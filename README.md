# THE LAST ARCHIVE

*You don't load the world. The Archive returns it to you.*

A short sci-fi game and a compression lab in one HTML file (double-click, works offline, no install). Every world —
geometry and textures, 41 MB — lives in one compressed archive inside the page. The Archive restores only the chunks you
approach, the game checks each against its sha256, and the GPU assembles them out of light; chunks you leave fold away.
The same chunks are packed three ways, and you can switch the decoder at any time (**M**): ACEAPEX, zstd, LZ4HC.

decoder: aceapex commit 8ae26bf

Demo written by the author of ACEAPEX. Prepared with AI (Claude) and checked by the author.

## What is inside
- **The game**: a Station hub and three worlds. The Forgotten City (light the lanterns in the order the echoes remember — each
  rebuilds a street), The Frozen Forest (turn ice mirrors to lead a beam to the frost heart), The Reactor (open the valves from
  lowest pressure to highest before the core cools). Three keys open The Heart of the Archive: the Guardian in three forms.
  Every world has a return door behind its entrance.
- **Archive Benchmark**: A Teleport (whole City, 26 chunks), B Single object (one 0.02 MB chunk, 200 in a row), C Fly-through
  (24 Forest cells; worst cell). Each chunk is verified once; timed passes run whole loops (browser timers are ~0.1 ms coarse).
- **Archive Lab**: Portal Duel (one scene restored by two decoders, per-chunk timings measured, replayed on two pedestals slowed
  by a stated factor; [R] replays at real speed), Stress Test (fragments requested at once → frames dropped at 60 Hz), chests
  whose volume is each archive's size.
- **Genome Jump**: human chr1 (UCSC hg38, 254 MB FASTA) in one ACEAPEX archive (59.7 MB) inside the page; a slider jumps
  anywhere and only the 64 KiB blocks under the window are decoded.

## What is compared, exactly
| | packing | where it is read |
|---|---|---|
| ACEAPEX | fast profile level 8, 256 KiB blocks, one archive for all chunks | region decode (C99 decoder, commit 8ae26bf) |
| zstd | 1.5.7, level 19, one frame per chunk, no content checksum | `ZSTD_decompressDCtx` |
| LZ4HC | 1.10.0, HC level 12, one block per chunk | `LZ4_decompress_safe` |

All three decoders are in one WebAssembly module built with the same flags (emcc 7.0.0, `-O3`, no SIMD) and run on one
thread. Sizes of the world archive: ACEAPEX 8 889 710 B (21.7 %), zstd 3 888 533 B (9.5 %), LZ4HC 7 064 100 B (17.2 %)
of 41 031 360 B. zstd makes the smallest archive; which decoder is fastest depends on the machine and browser.

## Where the numbers come from
Every number on screen is measured live on the machine running the page. Numbers in this README were measured on one
server (AMD EPYC 4344P, Chromium headless with a software GPU); run the benchmark on your machine for your own numbers.

## Honest limits
- One CPU core: a page opened from a file has no shared memory for threads.
- No decoder here catches every corruption on its own (we tested single-bit flips: all three sometimes return wrong data
  with success). The sha256 check per chunk is done by the game, not by the decoders. ACEAPEX regions carry no checksum.
- The worlds are procedural (generated by this repository's code), not production game assets.
- Without WebGL2 the game and the Portal Duel are off; Benchmark, Stress Test and Genome Jump still work.
- Checked on Chromium (Linux, headless, software GPU), Edge (Windows 11) and Firefox 159 headless (no WebGL there: the
  non-3D parts). Not checked: Safari, phones. Browser processes used up to ~1.5 GB with the genome open (software GPU).

## Build (one command) and the expected sha256
Pinned toolchain — any other version may produce other bytes:
- Python 3.10 + numpy 2.2.6 · g++ (packer) · emscripten (emsdk) 7.0.0 · node 24.19.0
- npm packages: three 0.170.0, esbuild 0.24.0 (`package.json` with `"type": "commonjs"` is part of the build)
- zstd 1.5.7 source (tar.gz sha256 eb33e51f49a15e023950cd7825ca74a4a2b43db8354825ac24fc1b7ee09e6fa3)
- lz4 1.10.0 source (tar.gz sha256 537512904744b35e232912055ccf8ec66d768639ff3abe5788d90d792ec5f48b)
- aceapex at commit 8ae26bf (its `src/` and `c/`)
- `chr1.aet` (59 659 568 B, sha256 5a4139c6064c75cb0730469b7454c21c92f6d92c3bc15b491d951d2f2c219611) is shipped as is: it was
  packed from UCSC hg38 chr1.fa (sha256 04ee6db2…08ee0) at ACEAPEX level 2, 64 KiB blocks, LIT_CHUNK = FSE_CHUNK = 64 KiB, with
  a packer linked to libzstd 1.4.8; it is not rebuilt by `build.sh` and is not in this repository (59.7 MB): it is attached to each Release. With it at
  `build/out/chr1.aet` the build gives the sha256 below; without it the page is built without Genome Jump (other bytes).

```
npm install    # three 0.170.0, esbuild 0.24.0
ACEAPEX=<aceapex@8ae26bf> ZSTD=<zstd-1.5.7> LZ4=<lz4-1.10.0> bash build.sh    # writes TheLastArchive.html
sha256sum TheLastArchive.html
# expected: 763b2432c4e89f3e4be3272d41c81b7d11d8d339321820a30b623be01a6cb158  (106 793 784 B)
```
